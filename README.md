# 面试舱 Interview Drill

知识库抽题 + AI 点评与追问的**面试背题工具**。把现成的面试讲义切成分层题库，
随机抽题 → 用自己的话答一遍 → 看要点覆盖度与讲义出处 → 追问 → 进待复习。

> 目标不是"刷题量"，而是**加深印象**：先回忆，再对照，才知道自己漏了哪几句。

## 核心机制

点评不是"你答得不错，但还要注意…"这种无法执行的话，而是**每一条判断都挂着证据**：

| 环节 | 做什么 | 依据 |
|---|---|---|
| **要点覆盖度** | 参考答案拆成 3~6 个要点，逐条判定「已答到 / 答到一半 / 漏答」 | 讲义里 BM25 检索到的本题参考片段 |
| **原文溯源** | 每个要点脚注出处（文件名 + 章节），可点开看命中的 4 段原文与相关度 | 真实讲义原文，不做改写 |
| **追问链** | ① 讲义原文序列里的下一问，点击即抽；② 自由追问时召回原文并标出处 | 讲义原文 + 检索命中片段 |

**引擎双轨**：默认跑**本地确定性引擎**（检索 / 拆要点 / 判覆盖全在浏览器内完成，作答不上传）；
留了云端大模型的适配位，用于生成式措辞与开放式追问，检索与出处仍走本地。

## 运行

零构建、零依赖、双击即开：

```
双击 index.html
```

`corpus.js`（题库语料）不入库 —— 它由第三方讲义切分而来，版权属原作者。
自行准备语料后运行：

```bash
python build-corpus.py    # 读取 .corpus-raw/ 下的讲义 md，产出 corpus.js
```

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 应用主体（单页，内联 CSS/JS） |
| `engine.js` | 本地引擎：分词 / BM25 / 要点拆解 / 术语标尺 / 覆盖度评分 / 答偏检测 / 追问链 |
| `corpus.js` | **不入库**，语料产物，见上方构建方式 |
| `build-corpus.py` | 语料构建脚本 |
| `design-spec.md` | 设计规范：结构 / 组件清单 / 交互流程 / 响应式 / 无障碍 / **引擎能力与边界** |
| `design-plan.md` | 视觉方案「默写纸与红笔」：配色 / 字体 / 版式 |
| `.smoke.cjs` | jsdom 交互冒烟测试 |
| `.render.cjs` | Playwright 多视口渲染验证 |

## 验证

```bash
npm install -D jsdom playwright-core    # 仅测试需要，运行时零依赖
node .smoke.cjs                          # 交互冒烟（宽屏）
NARROW=1 node .smoke.cjs                 # 交互冒烟（窄屏）
node .render.cjs                         # 四视口渲染 1440/1280/1024/390
```

## 设计

视觉主张是**横线作业纸 + 红笔**：纸 / 格 / 墨三色近乎无色，唯一的颜色留给批改红。

> **红笔只划「答了一半」的缺口。**
> 整条没答到不划（整段都是缺口等于没划），答到的不划（正确不着色），
> 每个缺口只划第一次出现且最多三处。

覆盖率不用百分比，用**方格记分格**：命中填墨块 / 半答打斜纹 / 漏答留红框空格。

细节见 [`design-plan.md`](./design-plan.md) 与 [`design-spec.md`](./design-spec.md)。
